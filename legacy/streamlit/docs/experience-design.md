# Progressive inquiry experience

Welcome → confirm model → choose or write a situation → inquire. Welcome is shown once per workspace; invalidating a model configuration blocks new requests without hiding existing work. Model settings remain native password widgets; custom components receive no credentials.

The model transition is a local, bounded timeline with a skip action and reduced-motion support. Component nonces prevent playback on unrelated reruns. Hover/focus preview remains entirely in the browser. Click/Enter selection alone triggers Python. Journey derives from confirmed configuration, prepared input and accepted replies.

The sidebar holds language and scope. The workbench stays compact, with a wider journey rail, chat tools, notebook and review briefing. Suggestions fill editable answer starters and never fabricate facts or send automatically. Regeneration validates a replacement question before changing the existing transcript and provenance; it consumes a request without adding a turn.

A cryptographically random, tab-scoped resume capability is kept in sessionStorage. Inquiry data lives only in bounded server memory for up to two hours; no API keys, consent or credential signatures are cached there. No token is placed in a URL. Refresh recovery is best effort: process restart/expiry can erase it. Download is the durable backup. New conversation replaces the saved inquiry.

Verification: state/core tests, native-widget AppTest, actual browser desktop/mobile interactions, deployment smoke test and source package integrity. Animation references: Hairline, GSAP timeline sequencing and native Web Animations; no animation CDN or framework dependency.
